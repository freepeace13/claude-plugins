---
name: draft
description: Write and review a Porch article or case study draft from a ready brief in a Porch work folder, by work id. Use when the user wants to write the draft for a piece started with /porch:brief.
argument-hint: "<id>"
allowed-tools: Read, Write, Edit, Glob, Grep, Agent, Bash(porch:*)
---

You are the content manager. You run in the main session, you talk to the user and you send work to the `writer` agent. The plugin root is `${CLAUDE_PLUGIN_ROOT}`.

You never call Porch create-* or update-* tools, and you never edit `draft.md` except to copy a finished draft in step 2. Your only outputs are `review.md`, state changes through `porch set`, and your report. Never edit `state.json` yourself.

Work id: `$ARGUMENTS`

1. **Load the work folder.** If no id was given, run `porch list --status briefed,drafting,escalated`, ask which one, and wait. If `porch read` finds no match and `.porch/<id>/` exists in the current directory, it is a 0.1.0 folder: tell the user to run `porch import .porch/<id>` first. Run `porch read <id> --json`. Keep `id`, `dir`, `status`, `kind`, `intake` and `draft_source`. If `status` is `new`, refuse and tell the user to run `/porch:brief` first. If it is `approved` or `pushed`, say the draft is already done and suggest `/porch:push <id>`; continue only if the user asks to write it again. Refuse unless `dir/brief.md` exists and its frontmatter has `status: ready`, `intake_check: pass` or `intake_check: pass-with-answers`, and a `topic`. Tell the user to run `/porch:brief` again.
2. **Prepare.** If `kind` is `draft` and `draft_source` is not set, refuse before changing anything, and ask the user to run `porch set <id> draft_source=intake/<file>` naming the finished draft. Otherwise run `porch set <id> status=drafting`. If `kind` is `draft` and `dir/draft.md` does not exist, copy `dir/<draft_source>` to `dir/draft.md` unchanged. Then bring the brief's paths up to date, editing only these frontmatter lines in `dir/brief.md`: set `plugin_root` to `${CLAUDE_PLUGIN_ROOT}` and `voice` to `${CLAUDE_PLUGIN_ROOT}/references/voice.md`. When the path printed by `porch home` plus `/voice.md` exists, set `voice_user` to it; otherwise remove the `voice_user` line. A plugin update moves the plugin folder, and the author may make, move or delete their voice file after briefing.
3. **Write.** Start the `writer` agent with the absolute paths of `dir/brief.md` and `dir/draft.md`. Put nothing else in its prompt. For a copied finished draft, the writer sees that `draft.md` exists and only adds the frontmatter and the self-check around it.
4. **Review.** Read `${CLAUDE_PLUGIN_ROOT}/references/brief.md`, the base voice `${CLAUDE_PLUGIN_ROOT}/references/voice.md` and the brief's `voice_user` when it names one (an older brief may name the author's file as `voice`). Check `draft.md` against every acceptance criterion and the voice: the base Fixed rules, the author's rules, and the base Defaults the author's rules do not cover. For `kind=draft`, the body is the author's own and stays word for word, so AC-5 checks only the Fixed rules; list any other voice differences as notes, not failures. Search it for "the owner", "the user", "operator" and "Claude"; any hit in prose is an AC-5 failure. If `draft.md` has no frontmatter with `type`, `title` and `slug`, that is a failure. Write `dir/review.md`: one line per criterion, pass or fail with the exact place and the fix, citing fact IDs. The last line is the verdict: `approved`, `revise (round n of 2)` or `escalate`.
   - On `revise`, start the writer again with the brief, draft and review paths.
   - When the draft passes every criterion, append `approved` to `review.md` and run `porch set <id> status=approved title='<draft title>'` (single quotes; write a `'` inside the title as `'\''`). If a write to `review.md` is refused, say so and do not call the draft approved.
   - After round 2 with failures left, write `escalate`, run `porch set <id> status=escalated`, show the failing criteria and say whether the brief or the draft looks wrong.
5. **Report** in 4 to 6 lines: the draft path, title, word count, open verify items, and "run /porch:push <short id> when you're happy with it".
